# Bullmet — этап 7: реальные ограничения по ролям

Что добавлено:
- Новый файл `lib/adminAccess.ts` с общей матрицей ролей и доступа.
- Новый контекст `components/AdminAccessContext.tsx`.
- `AdminGuard` теперь проверяет не только email из env, но и роль пользователя в `profiles`.
- В админку допускаются только роли:
  - admin
  - manager
  - content_manager
- Пользователь со статусом `blocked` не может войти в админку.
- Если роль не имеет доступа к разделу, показывается экран “Раздел недоступен”.
- Менеджер видит только доступные разделы: заказы, заявки, отзывы, статистика.
- Контент-менеджер видит только доступные разделы: главная, товары, медиа, баннеры.
- Администратор видит всё.
- Sidebar теперь фильтрует пункты меню по роли.
- Topbar показывает реальную роль пользователя.
- Логин теперь может отправлять staff-пользователя сразу в админку по роли, а не только по `NEXT_PUBLIC_ADMIN_EMAIL`.
- Добавлен SQL-файл `database/admin-role-access-hardening.sql`.
- SQL добавляет защиту от самостоятельной смены роли/статуса обычным пользователем через профиль.
- Проверка `npx tsc --noEmit` прошла успешно.

Важно:
- Для существующей базы выполнить `database/admin-role-access-hardening.sql`.
- Первый администратор всё ещё может входить через `NEXT_PUBLIC_ADMIN_EMAIL / NEXT_PUBLIC_ADMIN_EMAILS` — это нужно для bootstrap-доступа.
- После входа администратора можно назначать роли в `/admin/users`.
