# Миграции Supabase

`database/supabase-schema.sql` — единственная базовая схема для нового проекта. Корневой `supabase-schema.sql` устарел и применять его нельзя.

## Новый пустой проект

Выполняйте SQL Editor последовательно, останавливаясь при первой ошибке:

1. `database/supabase-schema.sql`
2. `database/20260920_security_hardening.sql`
3. `database/account-notifications.sql`
4. `database/review-control-settings.sql`
5. `database/site-page-redirects.sql`
6. `database/admin-activity-log-audit.sql`

Пункты 3–6 добавляют возможности, появившиеся после базовой схемы. После каждого файла проверяйте, что SQL Editor завершился без ошибок.

## Существующий проект

Не запускайте `database/supabase-schema.sql` повторно. Сначала снимите backup и сравните реальную схему с базовой. Затем применяйте только отсутствующие изменения из списка выше, в том же порядке. Скрипты без даты в этой папке — исторические этапы, уже включённые в актуальную базовую схему; повторно запускать их не требуется.

## Проверка после установки

1. Заполните `.env.local` по `.env.example`; `SUPABASE_SERVICE_ROLE_KEY` остаётся только на сервере.
2. Создайте активный профиль администратора в `public.profiles` через контролируемую процедуру Supabase.
3. Выполните `pnpm exec tsc --noEmit --incremental false && pnpm run build && git diff --check`.
4. Проверьте вход, админские API, публикацию товара, создание заказа и прямой доступ anon к таблицам по ролевой матрице из чек-листа.

Миграции не применяются приложением автоматически и не должны выполняться без проверки на тестовом проекте Supabase.
